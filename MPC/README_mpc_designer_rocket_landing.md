# MPC Designer サンプル: 再使用ロケットの着陸シミュレーション（対話的GUIチューニング）

MPC DesignerはModel Predictive Controlのコントローラ設計・チューニング・シミュレーションをGUIで行えるアプリです。`mpc_rocket_landing_demo.m`（`mpc`オブジェクトをスクリプトで直接組み立てる方式）と同じ1D suicide burn着陸問題を、今回はスライダーで重みを動かしながら応答をリアルタイムに確認できるGUIで扱います。

Reinforcement Learning Designerとは異なり、`mpcDesigner`関数は**組み立て済みの`mpc`オブジェクトを引数として直接渡せる**ため、コントローラの設計（プラントモデル・制約・重み）はスクリプト側でそのまま用意できます。GUI側で行うのは主に「シミュレーションシナリオ（初期条件・基準軌道）の設定」と「重みの対話的なチューニング」です。

## ファイル

- `mpc_designer_rocket_landing_demo.m` — プラントモデル・基準軌道・MPCコントローラを構築し、MPC Designerアプリを起動するスクリプト
- `mpc_designer_export_and_simulate.m` — アプリでチューニングして「Export」した`mpcobj`を使って、ロケット着陸のクローズドループシミュレーションとアニメーション（GIF保存込み）をMATLAB側で実行するスクリプト

## 必要環境

- MATLAB R2025b（動作確認済み）
- Model Predictive Control Toolbox
- Control System Toolbox

## 実行方法

MATLAB のカレントフォルダをこのディレクトリに設定し、以下を実行します。

```matlab
mpc_designer_rocket_landing_demo
```

コンソールにメッセージが表示された後、MPC Designerアプリのウィンドウが、`mpc_rocket_landing_demo.m`と同じ設計の`mpcobj`（プラント・拘束・重みを設定済み）を読み込んだ状態で開きます。

## アプリでの操作手順

1. **シミュレーションシナリオの設定**
   アプリの「Scenario」（シミュレーションシナリオ）関連のツールから、初期状態とシミュレーション時間を設定します。スクリプトがワークスペースに用意した変数を使います。
   - 初期状態: `x0 = [h0; v0] = [500; -60]`
   - 基準軌道（時間変化する目標値）: `tRef`、`hRef`（高度の基準）、`vRef`（速度の基準）
   これらは`mpc_rocket_landing_demo.m`で解析的に設計したものと同じ、「速度が線形に減少しちょうど`h=0`で着地する」実現可能な軌道です。参照信号をワークスペースからインポートする設定項目に`hRef`/`vRef`を割り当ててください。
2. **重みの対話的チューニング（Tuneタブ）**
   Tuneタブには、出力ごとの個別スライダーではなく、**「Weight」と「Estimation」という2本の総合調整スライダー**（それぞれ0〜100）があります。「Weight」スライダーは値を上げるほど追従を積極的（アグレッシブ）に、下げるほど穏やか（ロバスト）にする方向に、内部の全出力・全操作量重みをまとめて再スケーリングします（個別の出力に対して重みを別々に指定したい場合は、同タブの重み設定ダイアログから直接編集します）。スライダーを動かすと即座に内部の`mpc`オブジェクトが更新され、連動するプロットが自動的に再計算されます。
   本サンプルの初期重みは`Weights.OutputVariables=[1 1]`、`Weights.ManipulatedVariablesRate=0.05`です。`mpc_rocket_landing_demo.m`のREADMEで報告した通り、単純な原点レギュレーション（基準軌道を使わない場合）ではこの重みだけで軟着陸させるのは難しく、極端な値ではクラッシュまたはホバリングに陥ります。スライダーを動かしながらその境界を体感してみてください。
3. **ホライズンの調整**
   予測ホライズン・制御ホライズン（本サンプルではそれぞれ20、5ステップ）は、Structure（構造）関連の設定からも変更でき、変更するとシミュレーションへ反映されます。
4. **応答の確認**
   高度・速度がプロット上で基準軌道にどれだけ近いか、スロットルが`0`〜`1`の制約内に収まっているかを確認します。着地（高度が0付近）での速度が浅い角度で0に近づいていれば軟着陸、大きく振動・飽和していればクラッシュ相当の設計です。

## GUIでチューニングした結果をMATLABでシミュレーション（ロケットのアニメーション）する方法

MPC Designerのプロットはアプリ内蔵の応答表示であり、ロケットのアニメーションはここでは描画されません。チューニング結果を使ってロケットの着陸アニメーションを見るには、次の手順で「アプリで調整→ワークスペースへエクスポート→スクリプトでシミュレーション」という流れを使います。

1. Tuneタブのスライダー（または重み設定ダイアログ）で調整する。
2. Tuneタブ右側の「Analysis」セクションにある **Export** ボタンを押す。
   `mpc_designer_rocket_landing_demo.m`は`mpcDesigner(mpcobj)`という変数名でアプリを起動しているため、MPC Designerはこの変数名（`mpcobj`）をコントローラのラベルとして記憶しています。Exportを押すと、確認ダイアログなしで**チューニング後のコントローラがそのままベースワークスペースの`mpcobj`に上書きエクスポート**されます（`assignin('base','mpcobj', ...)`相当の動作です）。
   ※ Exportボタンのドロップダウンには「Generate MATLAB Script」（現在の設計を再現するコードを生成）もあり、こちらもチューニング結果をコードとして持ち帰るのに便利です。
3. MATLABのコマンドウィンドウで `mpc_designer_export_and_simulate` を実行する。
   このスクリプトは、ワークスペースにある**現在の`mpcobj`**（＝Exportした直後の値）を使って、`mpc_rocket_landing_demo.m`と同じクローズドループシミュレーション（`mpcstate`＋`mpcmove`のループ）を実行し、軌道プロットと着陸アニメーション（`mpc_designer_tuned_landing_animation.gif`として保存）を生成します。初期条件・基準軌道は、`mpc_designer_rocket_landing_demo.m`実行時にワークスペースへ残した`x0`/`hRef`/`vRef`をそのまま再利用します（無ければ既定値で自動生成します）。

スライダーを動かす → Export → `mpc_designer_export_and_simulate`を実行、を繰り返せば、GUIでの調整結果を毎回アニメーションで確認できます。

## `mpc_rocket_landing_demo.m`との違い

| | `mpc_rocket_landing_demo.m`（スクリプト） | `mpc_designer_rocket_landing_demo.m`（GUI） |
| --- | --- | --- |
| コントローラの構築 | `mpc(plant, Ts, P, M)` ＋ プロパティ代入 | 同じくスクリプトで構築し、`mpcDesigner(mpcobj)`にそのまま渡す |
| 重みの調整 | コードを書き換えて再実行（本サンプル開発時は何度も繰り返した） | スライダーをドラッグして即座に応答を確認 |
| シミュレーション実行 | `mpcstate`＋`mpcmove`の手動ループ | アプリ内蔵のシミュレーション機能 |
| 基準軌道・初期条件 | スクリプト内で変数として直接使用 | Scenarioエディタでワークスペース変数をインポート |
| 向いている用途 | 自動化・バッチ実行・最終的な成果物としてのコード | 重みやホライズンの当たりを素早くGUIで探索し、感覚を掴んでからコードに反映する |

## 補足

- `mpcDesigner`は`reinforcementLearningDesigner`と異なり、`mpc`オブジェクトを直接引数に取れるため、コントローラ設計自体はスクリプトで完結できます。GUIでしかできないのは「シナリオ設定」と「対話的なチューニング」の部分です。
- アプリはMATLABデスクトップ上のウィンドウとして開くため、この起動自体はスクリプトから自動化できますが、その先の操作（シナリオ設定・スライダー操作）は手動です。
- `mpc_rocket_landing_demo.m`のREADMEで報告した「素朴な原点レギュレーションでは重み調整が難しい」問題は、まさにこのアプリのスライダーで体感的に確認できます。基準軌道を使わずに`x0=[500;-60]`から目標`(0,0)`への追従だけを試すと、重みをどちらに振っても極端な挙動になることが視覚的に分かります。

## アレンジ例

- 基準軌道を使わず、目標を`(h,v)=(0,0)`の定値に設定した場合の挙動をスライダーで探り、`mpc_rocket_landing_demo.m`のREADMEで報告した失敗パターンを再現する
- プラントの質量・最大推力を変更し、実現可能性（フィージビリティ）が失われる境界をスライダーで探す
- Weightスライダーを両極端（0付近・100付近）にしてExport→`mpc_designer_export_and_simulate`を実行し、着地速度・燃料消費・アニメーションがどう変わるか比較する
