# Model Predictive Control Toolbox サンプル: 再使用ロケットの着陸シミュレーション

`rocket_landing_demo.m`（Reinforcement Learning Toolbox版）と同じ1D suicide burn着陸問題を、今度はModel Predictive Control（MPC）で解きます。RL版が試行錯誤（報酬設計・数百エピソードの学習）で方策を獲得したのに対し、MPC版は物理モデルを直接使って毎ステップ最適化するため、**学習は不要**で、**毎回決定論的に**同じ結果（軟着陸）が得られます。

## ファイル

- `mpc_rocket_landing_demo.m` — 基準軌道の設計・MPCコントローラ構築・クローズドループシミュレーション・可視化を行う単体スクリプト

## 必要環境

- MATLAB R2025b（動作確認済み）
- Model Predictive Control Toolbox
- Control System Toolbox（`ss`関数に使用。通常MPC Toolboxと共にインストールされています）

## 実行方法

MATLAB のカレントフォルダをこのディレクトリに設定し、以下を実行します。

```matlab
mpc_rocket_landing_demo
```

学習が無いため、実行はほぼ即時に完了します（RL版は学習に数分かかりますが、こちらは1秒未満〜数秒程度）。

## 問題設定

RL版（`README_rocket_landing.md`）とほぼ同じですが、状態は高度・速度の2次元のみ（燃料は状態に含めず、消費量は事後的にレポートするだけ）です。

| 項目 | 内容 |
| --- | --- |
| 状態 | 高度 `h`（m）、鉛直速度 `v`（m/s） |
| 入力 | スロットル（連続値、`0 <= u <= 1`） |
| 初期条件 | 高度500m、降下速度 -60 m/s |
| 成功条件 | 着地時（h=0）の速度が `abs(v) <= 5 m/s` |
| 質量・推力 | 質量25,000kg、最大推力450,000N（RL版と同一） |

## アプローチ: 基準軌道の追従

ロケットの運動方程式は状態`[h;v]`について線形（`dh/dt=v`、`dv/dt=(Tmax/mass)*u - g`）なので、MPC Toolboxの線形`mpc`オブジェクトをそのまま使えます。

素朴に「目標(h,v)=(0,0)へのレギュレーション」としてMPCを組むと、有限のホライズンでは「早く高度を減らそうとして速度超過でクラッシュする」か「速度超過を恐れてホバリングし続け着地できない」かのどちらかに転びやすく、コスト関数の重み調整が意外と難しい問題であることが分かりました（詳細は下記「詰まった点」）。そこで本サンプルでは、以下の2段階アプローチを取っています。

1. **基準軌道を解析的に設計** — 速度が `v0` から `0` まで線形に減少する軌道 `v_ref(t) = v0*(1 - t/T)` を考えると、これを積分した高度も同時刻 `T = -2*h0/v0` でちょうど `h=0` に到達します。この軌道は最大推力の範囲内で常に実現可能（本サンプルの数値では終始スロットル約0.745の定常噴射で追従可能）であることを事前に確認しています。
2. **MPCで基準軌道を追従** — MPCの役割を「軟着陸の仕方を考える」ことから「あらかじめ分かっている良い軌道から外れないようにする」ことに単純化します。MPCが得意とする、拘束（`0<=u<=1`）を守りながらの高精度な追従制御という強みを素直に活かせる設計です。

## やっていること

1. **基準軌道の生成** — `vRef(t)`、`hRef(t)` を解析式で計算
2. **プラントモデル構築** — 状態空間モデル `ss(A,B,C,D)` で二重積分器を定義し、重力を`Model.Nominal.DX`（公称動作点での状態微分）としてアフィン項を持たせる
3. **MPCコントローラ構築** — `mpc(plant, Ts, PredictionHorizon, ControlHorizon)`、スロットル制約、出力のスケールファクタ、追従重みを設定
4. **クローズドループシミュレーション** — `mpcstate`と`mpcmove`を使い、毎ステップ真の状態を直接与えて（推定器をバイパスして）最適スロットルを計算し、運動方程式をオイラー法で1ステップ進める。高度が0以下になったら終了
5. **可視化**
   - 高度・速度の実軌道と基準軌道の比較、スロットル指令の時系列（3段プロット）
   - 着陸アニメーション（RL版と同じ見た目）を表示すると同時に、`mpc_rocket_landing_animation.gif` として保存

## RL版との比較

| | `rocket_landing_demo.m`（RL） | `mpc_rocket_landing_demo.m`（MPC） |
| --- | --- | --- |
| アプローチ | 報酬設計＋400エピソードの試行錯誤学習 | 物理モデルを直接使った毎ステップ最適化 |
| 実行のたびの結果 | 学習の乱数性により変動しうる（チェックポイント保存で対策済み） | 常に同じ（決定論的） |
| 実行時間 | 学習に約2分 | 1秒未満〜数秒 |
| スロットル | 6段階の離散値（DQN） | 連続値 |
| 着地速度（手元の実行例） | -4.47 m/s | -3.61 m/s |
| モデルの利用 | 環境の物理式は「報酬」を通じてしか間接的に伝わらない | `A`,`B`行列として直接組み込む |
| 未知環境への対応 | 環境モデルが分からなくても学習で獲得できる | 正確な物理モデルが必要（モデル誤差に弱い） |

大まかに言えば、**正確な物理モデルが分かっているなら圧倒的にMPCが手軽で信頼できる**（今回のように毎回同じ好結果が即座に得られる）一方、**モデルが分からない・複雑すぎて立式できない場合はRLに分がある**、という強化学習と古典制御の典型的なトレードオフが、同じ着陸問題を通じて対比できます。

## 詰まった点・設計上の工夫

- **`(h,v)=(0,0)`への素朴なレギュレーションは失敗しやすい**: 出力の重み `Weights.OutputVariables` をどう振っても、高度重視だと減速が間に合わずクラッシュ、速度重視だとホバリングして着地できない、という極端な挙動になりがちでした。有限ホライズンMPCで「今は遠くにある目標に向けた立ち上がり」と「目標到達後の安定」を単一の重み設定で両立させるのは、LQRの終端コスト（リカッチ方程式の解）を使うなど本来もう一段の工夫が必要な問題です。本サンプルでは、代わりに実現可能な基準軌道を追従させることでこの難しさを回避しています。
- **終端制約（`setterminal`）も単純には効かない**: 「ホライズン終端で`(h,v)=(0,0)`」というハード制約を毎ステップの移動ホライズンで課しても、「今から`P`ステップ先に着けばよい」という制約は現在時刻を問わず常に満たせてしまうため、コントローラが着陸を先延ばしにする（スロットル0のまま自由落下する）挙動になりました。固定の終端時刻を持つ「着陸」のような一回性のタスクには、移動ホライズンの終端制約はあまり適していません。
- **既定の状態推定器が追従に遅れを生む**: `sim(mpcobj, ...)`関数（既定の状態推定器を内部で使用）で基準軌道を追従させると、出力2（速度）に既定で付与される積分外乱モデルの影響で追従に明確な遅れが生じ、着地速度が大幅に超過しました（クラッシュ相当）。今回は状態を完全に観測できる設定なので、`mpcstate`オブジェクトの`Plant`プロパティに真の状態を直接与えることで推定器をバイパスし、遅れのない正確な追従を実現しています。

## アレンジ例

- `safeVelocity`や初期条件（`h0`,`v0`）を変えて、基準軌道の再設計込みでどう追従するか確認
- `PredictionHorizon`/`ControlHorizon`を短くして、追従精度と計算コストのトレードオフを確認
- プラントに意図的なモデル誤差（例: 質量を実際と変えて渡す）を与え、MPCの頑健性・オフセットをRL方策と比較
- 2次元（水平方向の運動＋機体傾斜）に拡張し、より本物のFalcon 9の着陸誘導（凸最適化ベースの実際の手法に近い）に近づける
